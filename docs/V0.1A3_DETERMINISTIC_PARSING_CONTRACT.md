# V0.1A.3 Deterministic Document Parsing Contract

## Purpose

V0.1A.3 converts an immutable `document_version` into persistent, addressable
`source_units`. It is an ingestion/evidence capability, not a semantic
reasoning capability.

## Design principles

1. No generative AI is used for parsing.
2. The physical file checksum must match the registered `document_version.sha256`
   before parsing is allowed.
3. Parser identity, parser version and canonical configuration are persisted.
4. Identical input + identical parser version + identical configuration must
   produce the same `run_fingerprint`, ordered unit fingerprints and
   `result_sha256`.
5. Source units retain format-specific locators.
6. Semantic labels such as Tujuan, Sasaran, Program, Kegiatan or Indikator are
   intentionally deferred to later ontology/entity-extraction stages.
7. Failed parsing is recorded; partial source units are not committed.
8. Default parse calls are idempotent: an existing successful run with the same
   fingerprint can be reused. `force=true` exists for reproducibility testing.

## V0.1A.3 source-unit vocabulary

### PDF
- PAGE
- TEXT_BLOCK

PDF text blocks include one-based page number and bounding box coordinates.

### DOCX
- PARAGRAPH
- TABLE
- TABLE_ROW
- TABLE_CELL

DOCX does not claim rendered page numbers because python-docx is not a layout
engine. Provenance is structural (block/table/row/cell path).

### XLSX
- SHEET
- TABLE_ROW
- TABLE_CELL

XLSX locators retain sheet name/index, row, column and cell coordinate.

## Boundary

This stage does not infer:
- planning ontology entities,
- semantic relationships,
- regulatory meaning,
- coherence findings,
- recommendations.

Those later capabilities must cite these source units rather than bypassing
them.

## Permanent capability gained

`immutable document version -> deterministic parsing run -> granular source
units -> stable hashes + locators -> reusable institutional evidence`
