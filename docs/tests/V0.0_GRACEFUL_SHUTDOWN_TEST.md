# Planning Intelligence V0.0 - Graceful Backend Shutdown Test

Test date: 2026-09-26

## Purpose

Verify that the backend receives Docker shutdown signals correctly and exits gracefully instead of being force-killed with exit code 137.

## Startup configuration

Backend startup command uses:

alembic upgrade head && exec uvicorn app.main:app --host 0.0.0.0 --port 8000

Using `exec` makes Uvicorn the main process inside the container so it can receive Docker SIGTERM directly.

## Shutdown result

Docker command:

docker compose stop -t 20 backend

Observed container state:

Status=exited
ExitCode=0
OOMKilled=false

## Uvicorn shutdown evidence

INFO: Shutting down
INFO: Waiting for application shutdown.
INFO: Application shutdown complete.
INFO: Finished server process [1]

## Restart verification

Backend restarted successfully.

Direct Docker-network health check:

{"status":"ok","version":"0.0.1","ai_provider":"NO_AI"}

Proxy health check through localhost:8080:

status      : ok
version     : 0.0.1
ai_provider : NO_AI

## Verdict

PASS

The previous backend exit-code-137 issue is resolved. Uvicorn now shuts down gracefully with exit code 0, is not OOM-killed, and successfully recovers after restart.

## Operational note

During forced backend container recreation, the current Nginx frontend may temporarily retain the previous backend container address. This is a separate service-discovery/proxy concern for a later version and does not affect normal backend stop/start behavior verified by this test.
